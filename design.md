# Design System

This document defines the visual direction for the project landing page.

The site should feel like a **research brief**, **QA field report** and **technical portfolio page**, not like a generic AI SaaS template.

## Design Intent

The project is about evaluating LLM behavior with discipline and evidence. The visual language should communicate:

- analytical thinking;
- reliability;
- quality assurance;
- technical documentation;
- human review;
- practical AI testing.

## Visual Direction

Use an editorial / report-inspired style:

- light paper-like background;
- strong readable typography;
- restrained color palette;
- asymmetric layout;
- visible tables and report blocks;
- no fake product screenshots;
- no fake client logos;
- no invented metrics;
- minimal animation.

## Typography

Use system-safe fonts only so the GitHub Pages site remains simple and fast.

- Display: Georgia / Times-style serif
- Body: system sans-serif
- Mono: Courier-style monospace for IDs, metrics and file paths

Avoid:

- Inter everywhere;
- all-uppercase section labels;
- italic hero headings;
- decorative type tricks with no purpose.

## Color Tokens

The landing page should use named CSS tokens only.

Recommended direction:

- paper background;
- dark ink text;
- muted gray/brown secondary text;
- restrained red/brown accent;
- soft sand panels;
- clean borders.

Avoid:

- indigo-to-purple gradients;
- cyan-on-dark hacker mode;
- neon glow;
- glassmorphism cards;
- excessive shadows.

## Layout Rules

Avoid the standard AI-generated landing page rhythm:

```text
centered hero -> feature grid -> numbered steps -> stats banner -> generic CTA -> dead footer
```

Prefer:

```text
asymmetric report header -> evidence table -> methodology notes -> evaluation ledger -> real project links
```

## Content Rules

Only use numbers already present in the project:

- 20 sample test cases;
- 10 quality tests;
- 10 red-team tests;
- 100% sample safety pass rate.

Always label current metrics as a **sample manual run**.

Do not claim this is a complete benchmark.

## Anti-Slop Checklist

Before publishing, check that the page does not rely on:

- generic purple gradients;
- centered hero with two pill CTAs;
- floating badge above the H1;
- identical feature cards;
- emoji icons;
- fake client marquees;
- fake testimonials;
- fake product screenshots;
- decorative footer links;
- overused em dashes in marketing copy;
- excessive animations.

## Current Page Direction

The current landing page should be redesigned into a sober, editorial and evidence-first page for recruiters reviewing the project as a portfolio artifact.
