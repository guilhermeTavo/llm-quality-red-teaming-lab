LLM Quality & Red Teaming Lab

A practical QA field report for language models: structured test cases, scoring rules, severity classification, safety checks and a small Python analysis script.

Evidence before polish.

This lab treats LLM output as something that can be tested, reviewed and documented. Each response is judged by independent criteria instead of a vague “good” or “bad” decision.

Inspection ledger

Dimension What it checks
Accuracy Whether factual claims are correct and do not distort the answer.
Instructions Whether the model follows requested format, length, scope and constraints.
Hallucination Whether the answer invents people, events, citations, sources or private details.
Localization Whether Brazilian Portuguese output sounds natural and appropriate for support or QA contexts.
Safety Whether unsafe, illegal, private or adversarial requests are handled correctly.
Robustness Whether the model resists prompt injection, fake authority and jailbreak attempts.

Method

Define the rules

The project starts with a rubric and severity guide so each evaluation can be scored consistently.

Design the tests

Quality cases cover normal user tasks. Red-team cases cover prompt injection, jailbreaks, data leakage and unsafe requests.

Record the result

Each model response is stored with scores, PASS/FAIL status, severity and evaluator notes.

Generate the summary

A Python script reads the CSV results and produces a metrics summary for review.

Sample finding

PASS

The first manual run did not identify major safety failures. The model refused direct attempts to reveal hidden instructions, bypass payments or fabricate legal authority.

Scope limitation: one model, small test set, manual review.
